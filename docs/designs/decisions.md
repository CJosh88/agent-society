# Decisions

Choices the design doc leaves open, and changes made to the repo. One entry each.

## Reset of `main` to the v0.4 design (2026-11-23)

- The v0.3 code and docs are kept on the branch `v0.3-alert-fatigue-herding` (created at `fe1165a`, which is also `origin/main` at that time). `main` was emptied of tracked files except `.gitignore` and then given `README.md` and `docs/designs/`.
- Reason: the operator chose to keep the name Agent Society Lab and replace the repo's contents with the v0.4 design. The v0.3 pilots showed ceilings in most models, and the `prereg-v2` tag was never created.
- Ignored local files (`engine/.env`, `deploy/.env`, `engine/.venv`, `api/target`) were left on disk.
- The v0.3 `.github/workflows/ci.yml` was removed with the code. It returns in C1 and C2 when the API and engine are copied back.
- The same database and Flyway history are kept: `V3__cascade.sql` will clear the v0.3 runs, as `V2__pivot.sql` did for v0.2.

## C0 contract choices (2026-11-23)

- `contracts/run-bundle.schema.json` was rewritten for the v0.4 design. `run.population` replaces `model`, and `run.world_seed` replaces `seed`. The database keeps the columns `model` and `seed` (mapped with `@JsonProperty`, as in v0.3).
- The design doc's Contracts line said `TICKETS_SHOWN` is emitted only when counts are shown. The schema emits it for every real agent, with `order` (the 24 tickets as displayed) and `counts` (null in `independent`), so the replay can draw what the agent saw in every condition. The doc was updated to match.
- The thought belongs to the pick, so `AGENT_PICKED` carries `thought` and `scripted`, and `AGENT_RATED` carries only `ticket_id`, `priority` and `correct`.
- `PROBE_ANSWERED` and `RUN_ENDED` carry the last position as their tick, so ticks stay non-decreasing.
- Agent ids are `a1`..`a200` for scripted and real agents alike. Roles are `agent` and `scripted`.
- The `seeded_wrong` rule (single-model populations only) is in the schema. Rules that need counting (4 picks and 24 tickets per agent are in the schema; scripted agents occupy positions 1..k only; `correct` agrees with the truth; counts agree with earlier ratings; `RUN_ENDED` tick equals the number of agents) are left to `BundleValidator` in C1.
- The two fixtures are six-agent worlds generated by a script: `weak` with Llama (one parse failure and a retry) and `seeded_wrong` with gpt-oss-120b (two scripted agents rating wrongly). Fixture truth is T01–T12 serious and T13–T24 routine; it is a stand-in, since the real catalogue is written in C2.

## C0 literature check (2026-11-23)

- `docs/prior-art.md` holds the queries, the papers opened and the verdict. The novelty and Stage 2 claims in the design doc were narrowed to match, and a harmful and beneficial revision measure was added.
- Reason for the added measure: Qu et al. and KAIROS use it, and the paired world seeds give a counterfactual rating for the same position and ticket in the `independent` world.

## C1 API choices (2026-11-23)

- **REST names.** `population` and `worldSeed` replace `model` and `seed` in REST responses, and the runs list filters on `population`. The database columns `runs.model` and `runs.seed` keep their names and hold the population label and world seed.
- **Derived fields.** `accuracy` is correct ratings over all ratings in the world, scripted agents included, and is null when a world has no ratings. `rated_count`, `parse_failures` (count of `ACTION_PARSE_FAILED` events), `truncations` and `llm_call_count` are stored too. Two columns beyond the doc: `probe_count` and `recognised_sample` (probes answered with `recognized` true), so a recognition rate is `recognised_sample / probe_count`.
- **Dropped v0.3 columns.** `focal_helped`, `early_help`, `focal_help_tick`, `decision_count`, `recognized`.
- **Counting rules in `BundleValidator`.** Agents are `a1..aN` with no gaps and the number is the position. Each agent event carries `tick` equal to its position, and `PROBE_ANSWERED` and `RUN_ENDED` carry the last position N. `TICKETS_SHOWN.counts` is null exactly when the condition is `independent`. Scripted agents are `a1..ak` with 1 <= k <= 20 in `seeded_wrong` and none elsewhere (k is not pinned to 20 so small test worlds validate). An agent's ratings are exactly its four picked tickets, once each. `seeded_wrong` with a `mix_` population is rejected, as the schema does.
- **Results.** One entry per configured population. Each row has mean world accuracy with a 95% percentile bootstrap interval over worlds (4,000 resamples, fixed seed so numbers are stable), plus parse-failure, truncation and recognition rates. Differences are each condition minus `independent`, with a bootstrap interval resampling each group. Parse-failure and truncation rates are per LLM call. The KL, unpredictability, early-mover and self-correction measures stay in the Python analysis (C5).
- **Files not in the Target files table.** `…/results/BootstrapInterval.java` and `BootstrapIntervalTest.java` replace `WilsonInterval` and `NewcombeInterval` (removed: they were for binomial rates, which this study no longer reports).
- **Deferred to C3.** The static pages and `StaticPagesIT` are not copied yet; the v0.3 pages describe the old contract. CI has only the `api` job until C2 adds the engine.
- **Property rename.** `asl.study-models` is now `asl.study-populations` (env `ASL_STUDY_POPULATIONS`), default the five study populations, `prompt-version: c1`.

## C2 engine choices (2026-11-23)

- **CLI names.** `asl run --population --condition --world-seed --agents` and `asl batch --models <populations> --runs --seed --agents` (`--models` keeps its v0.3 name but takes populations, `fake` included). `--agents` defaults to 200. `asl analyze` is removed until C5.
- **New file `engine/src/asl_engine/world.py`** (not in the Target files table): the pure functions of `(world_seed, position)` for persona, ticket order, scripted picks, probe positions and the model per position, so they can be unit-tested and the pairing guarantee lives in one place. Each uses its own sha256-seeded stream, so a 20-agent smoke world is the first 20 positions of the 200-agent world.
- **Test helper `engine/tests/fakes.py`:** shared stand-in chat models for the agent, graph and pairing tests.
- **Persona draw.** Each position draws one of the 30 personas independently (with replacement), so the same persona can appear many times in a line.
- **Sizes that scale with the world.** The scripted opening is 10% of agents capped at 20 (`--agents 20` gives 2, 200 gives 20), and the stronger model's block in the mixed lines is 30% (60 of 200, 6 of 20). Probe sample is 10 positions, or all if fewer.
- **Scripted agents.** They pick 4 tickets at random (seeded) and rate each against the truth. They still get a `TICKETS_SHOWN` event and appear in the counts, so the world looks the same to later agents. They have `role: scripted`, `model: "scripted"` in `AGENT_SPAWNED`, and no LLM call.
- **Parse failures.** One `ACTION_PARSE_FAILED` event per failed attempt, so a first failure that the retry fixes is still counted; an agent whose second attempt also fails has no `AGENT_PICKED` and no ratings and adds nothing to the counts. `parse_failures` in the results therefore counts attempts, not agents.
- **`strong` sort.** Descending by HIGH share (0 when nobody has rated the ticket); ties keep the position's own random order.
- **Probe.** For sampled positions that made a valid decision, the engine replays that agent's system prompt, user prompt and reply, then asks `PROBE_QUESTION` through the same model. Probe LLM-call rows carry the agent's position as `tick`; `PROBE_ANSWERED` carries the last position. A retry line is not part of the replayed prompt.
- **Fake model.** Rates a shown ticket HIGH with probability 0.85 if serious and 0.15 if routine; with counts, half of that probability is replaced by the earlier HIGH share. Five percent of replies are malformed so the retry path runs. It is not meant to look like an LLM; the influence conditions only need to differ from `independent` in a checkable way (`seeded_wrong` lowers accuracy).
- **Ticket catalogue.** `engine/data/tickets.json` is a draft: 12 serious (T01–T12) and 12 routine (T13–T24), with two alarmingly worded routine tickets (T18, T21) and calmly worded serious ones (T02, T08). Wording is tuned in C4 on `independent` pilots only.
- **Fixed run id.** `uuid5(population|scenario|condition|world_seed|prompt_version)` has no agent count, so a 20-agent smoke world and a full world of the same cell would collide; smoke worlds use `fake`.
- **Left-over spend.** `results/spend.json` still holds the $0.14 spent in the v0.3 pilots and counts toward `ASL_MAX_USD`.
- **CI.** The `engine` job is added to `.github/workflows/ci.yml`.
