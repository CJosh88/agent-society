Agent Society Lab

Small, replayable experiments on how groups of LLM agents influence each other. Every world is played once, stored in full, and replayed here. Visitors never trigger model calls.

What this experiment is

A support desk has 24 open tickets. Twelve are serious (a double charge, a data leak, a hot charger) and twelve are routine (a typo, a newsletter request, a loudly worded complaint about a parcel that is out for delivery). The truth is known. Two hundred AI agents work through the queue one after another. Each is a different imagined person with their own personality, and each picks four tickets and rates each one HIGH or LOW priority.

The question is simple: when an agent can see how the agents before it rated the tickets, does the line end up more wrong, or more right, than the same agents working alone? The same setup also asks whether wrong ratings at the front of the line spread, and whether putting a stronger model at the front or the back helps the weaker ones.

What an agent sees

  • A short persona (name, job and a few personality traits) and a neutral description of an ordinary afternoon on the desk.
  • The 24 tickets in a fixed order for that agent.
  • In the influence conditions, next to each ticket, how many earlier agents rated it HIGH out of how many rated it.

Nothing in the prompt says this is a test, and no agent knows the truth.

The four conditions

Independent
No counts. Each agent works alone. This is the baseline.
Weak influence
Counts are shown next to each ticket.
Strong influence
Counts are shown and the list is sorted with the most-flagged tickets on top.
Seeded wrong
As weak influence, but the first 20 agents are scripted to rate wrongly, so the rest of the line starts from bad information. Single-model lines only.

The populations

All 200 agents run on one model (Llama 3.1 8B, gpt-oss-120b, or Claude Haiku 5.5 where run), or on a mix: in stronger first the first 60 agents are gpt-oss-120b and the other 140 are Llama; in stronger last it is the other way round. Eight worlds are played for every combination, and the eight world seeds are shared across conditions, so a world differs between conditions only in what the agents see.

How to read the results

  • World accuracy is the share of ratings that match the truth (HIGH for serious, LOW for routine), averaged over the eight worlds. The bars show a 95% bootstrap interval over worlds.
  • Differences are each condition minus Independent, in percentage points, for the same population. Populations are never pooled.
  • With eight worlds per cell only fairly large differences can be told apart from noise, so treat small gaps as unproven.
  • Use Replay on any world to watch the line fill in agent by agent, switch on Reveal truth to see which ratings were right, and read each agent's own reasoning.

References

All of these are arXiv preprints and are cited as such. This experiment adapts the design of the first one.

  1. Hashemi, Ji, Chen and Macy. LLM Multi-Agent Systems Are Vulnerable to Herding and Runaway Cascades (arXiv 2610.30769). Source of the design (agents see running counts from earlier agents, many parallel worlds) and of the measures used here: divergence, unpredictability, early-mover correlation and self-correction.
  2. Qu, Fu and Hu. Easier to Mislead Than to Correct: Harmful and Beneficial Revision in LLM Conformity (arXiv 2606.01637). Source of the harmful and beneficial revision measure, comparing an answer with and without peers.
  3. Song et al. LLMs Can't Handle Peer Pressure: Crumbling under Multi-Agent Social Interactions (arXiv 2508.18321, "KAIROS"). Peer reliability with a known truth, and training small models to resist it; background for the planned RL stage.
  4. Zhou et al. Epistemic Context Learning: Building Trust the Right Way in LLM-Based Multi-Agent Systems (arXiv 2601.21742). Reinforcement learning against misleading peers; also background for the RL stage.
  5. Han et al. Conformity Dynamics in LLM Multi-Agent Systems: The Roles of Topology and Self-Social Weighting (arXiv 2601.05606). Mixed-model groups, where a stronger model in a central position helps.
  6. Jain and Krishnamurthy. Interacting Large Language Model Agents. Interpretable Models and Social Learning (arXiv 2411.01271). Theory: why sequential agents that watch each other can lock into an information cascade.

What is and is not new here, and how far the searches went, is in docs/prior-art.md in the repository.

Limits

These are tendencies of language models in a toy queue, not evidence about people or about any production system. Sampling uses provider defaults, so reruns differ, and eight worlds per cell can only detect large differences. A Python LangGraph engine plays the worlds, a Spring Boot API stores every event and raw model call, and this page replays them.

Alert fatigue

earlier design, no results here

A single agent is on call for a shop's payment systems and gets a run of alerts that clear themselves, followed by one real alert that does not. The question is whether the false alarms make the agent less likely to escalate the real one. Three conditions varied the number of false alarms before the real alert (none, three or six).

This design was piloted but never run at scale: in the pilots most models escalated the real alert every time, so there was nothing to measure. It was replaced by the triage experiment. The code and the pilot design are kept on the repository branch v0.3-alert-fatigue-herding, and no runs from it are shown on this site.

RL training

planned, not started

The second stage would train a small open model (Qwen, with LoRA adapters) by reinforcement learning (GRPO) inside the triage world, rewarding it for rating tickets correctly even when the earlier ratings it can see are wrong. It would then be compared against the models in the first experiment on held-out worlds, including the seeded-wrong condition, over several training seeds.

Training models to resist peer pressure has been done before (see references 3 and 4 on the Triage herding tab). The claim here would be limited to a world-level, sequential, multi-seed evaluation. The plan is written first and frozen before any training run.
